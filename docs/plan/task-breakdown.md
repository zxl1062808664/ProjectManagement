# 任务拆解

## 阶段总览

项目按 5 个实施阶段推进：

1. 基础设施与全栈骨架
2. 认证与持久化核心
3. 项目/任务领域扩展
4. 同步与完整体验打磨
5. 验证、文档与交付

## Phase 1: 基础设施与全栈骨架

### T1.1 初始化 Node.js 项目和目录结构

- 优先级：P0
- 估时：M
- 依赖：无
- 说明：创建 `package.json`、基础脚本、`server/`、`public/`、`data/` 等目录，确定静态资源与服务端入口位置。
- 验收标准：项目可通过 `npm install` 安装依赖，目录结构可支撑后续前后端扩展。

### T1.2 搭建 Express 服务骨架

- 优先级：P0
- 估时：M
- 依赖：T1.1
- 说明：实现静态资源托管、健康检查接口、统一错误处理中间件和基础路由装配。
- 验收标准：启动后可通过 HTTP 访问页面与 `/api/health`。

### T1.3 重组前端静态资源并保持现有看板可用

- 优先级：P1
- 估时：M
- 依赖：T1.2
- 说明：将当前前端代码迁移到新结构下，保证页面样式和基础功能不被破坏。
- 验收标准：迁移后现有任务看板 UI 和本地功能仍可访问。

### T1.4 增加开发脚本和运行说明

- 优先级：P1
- 估时：S
- 依赖：T1.2
- 说明：补齐 `dev/start/test` 脚本、环境说明和基础 README。
- 验收标准：新开发者只看 README 即可启动项目。

## Phase 2: 认证与持久化核心

### T2.1 设计并初始化 SQLite schema

- 优先级：P0
- 估时：L
- 依赖：T1.2
- 说明：创建用户、会话、项目、任务、子任务、标签和关联表的 schema 初始化逻辑。
- 验收标准：数据库初始化脚本可重复执行且不会破坏已有结构。

### T2.2 实现注册/登录/登出/会话校验 API

- 优先级：P0
- 估时：L
- 依赖：T2.1
- 说明：完成密码哈希、token 生成、会话持久化与认证中间件。
- 验收标准：用户可注册、登录、保持会话并安全登出。

### T2.3 构建前端认证界面和会话恢复

- 优先级：P0
- 估时：M
- 依赖：T2.2
- 说明：新增注册/登录 UI、会话恢复、未登录与已登录视图切换。
- 验收标准：刷新页面后可恢复登录态，未登录用户无法访问云端工作区。

### T2.4 打通受保护接口与错误处理

- 优先级：P0
- 估时：M
- 依赖：T2.2、T2.3
- 说明：统一处理 401/403/422/500 等错误，确保前后端会话状态一致。
- 验收标准：会话失效、参数错误和服务端异常均有明确反馈。

## Phase 3: 项目/任务领域扩展

### T3.1 实现项目 CRUD 与项目切换

- 优先级：P0
- 估时：L
- 依赖：T2.4
- 说明：支持项目创建、编辑、归档、切换与项目范围内的数据展示。
- 验收标准：一个账号可维护多个项目，且数据互不混淆。

### T3.2 实现任务与子任务 CRUD

- 优先级：P0
- 估时：L
- 依赖：T3.1
- 说明：扩展现有任务结构，加入子任务编辑、完成状态和进度聚合。
- 验收标准：任务详情能管理多个子任务并准确展示完成进度。

### T3.3 实现标签 CRUD 和任务标签绑定

- 优先级：P1
- 估时：M
- 依赖：T3.1
- 说明：支持按项目维护标签，任务可关联多个标签并通过标签筛选。
- 验收标准：标签增删改查正常，任务卡片可显示并筛选标签。

### T3.4 实现 JSON 导入导出

- 优先级：P1
- 估时：M
- 依赖：T3.1、T3.2、T3.3
- 说明：定义导入导出结构，支持用户备份和恢复。
- 验收标准：可导出完整项目数据，并在校验通过时重新导入。

### T3.5 将前端数据源切换为 API 驱动

- 优先级：P0
- 估时：L
- 依赖：T3.1、T3.2、T3.3
- 说明：把当前 `localStorage` 主数据流改造为 API 拉取和提交。
- 验收标准：登录态下的主要任务操作均由服务端持久化驱动。

## Phase 4: 同步与完整体验打磨

### T4.1 增加游客模式与云端模式双通道

- 优先级：P1
- 估时：L
- 依赖：T3.5
- 说明：未登录时继续可本地使用，登录后切换到账号云端数据。
- 验收标准：两种模式边界清晰，不会相互污染数据。

### T4.2 实现首次登录导入/合并流程

- 优先级：P1
- 估时：M
- 依赖：T4.1、T3.4
- 说明：当浏览器已有游客数据时，为当前账号提供导入入口。
- 验收标准：用户可显式选择是否导入本地数据，导入结果可追踪。

### T4.3 扩展 UI 支持多项目、标签、子任务和同步状态

- 优先级：P0
- 估时：L
- 依赖：T3.2、T3.3、T4.1
- 说明：在现有界面风格下补齐项目导航、标签筛选、子任务区域和同步状态提示。
- 验收标准：完整流程在单页中可操作，且桌面/移动端都可用。

### T4.4 打磨空状态、错误状态和可访问性

- 优先级：P1
- 估时：M
- 依赖：T4.3
- 说明：补齐网络错误、空项目、空任务、导入失败等提示，并优化键盘与表单体验。
- 验收标准：关键操作在异常场景下仍可理解、可恢复。
